Add a polygon spatial reader to `@i4sea/zarr-node/spatial`. `readPolygon(arr, opts)` streams, one time step at a time, only the cells geometrically inside a lat/lon polygon of a `[time, ...spatial]` array (ray-cast, concave-correct), yielding a `Float64Array` of the in-polygon values per step in row-major bounding-box order. It reads each step as a bounding-box block sharing one `MemoryCache`, so every bbox-overlapping chunk is fetched/decompressed at most once and peak working memory stays bounded to ~one time slice regardless of the time extent. `resolvePolygonCells(arr, opts)` exposes the time-invariant selection (`cells` + `bbox` + applied `stride`) without reading values. Three coordinate layouts are supported: `{ kind: "1d", lat, lon }` (monotonic axes via binary search), `{ kind: "2d", grid }` (curvilinear `GridIndex`), and `{ kind: "npoints", lat, lon }` (unstructured points). An optional `maxCells` budget applies a clamped uniform stride (reported as `selection.stride`; no default cap, and a non-empty polygon never sub-samples to zero). Additive only — the point-read path is untouched. `GridIndex` gains `latAt(i, j)` / `lonAt(i, j)` accessors.
